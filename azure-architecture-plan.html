Azure OT Hybrid Infrastructure Plan

Migrated architecture definition & Purdue model mapping · CONFIDENTIAL – System infrastructure migration document

Target host hypervisor: VMware ESXi on Azure Dedicated Hosts / nested compute · Primary storage target: OTCYBERDATAStorage (mapped NetApp Files / shared Azure disks) · Static management IPv4: 10.0.0.150

1. Executive Summary & Migration Strategy

This architectural specifications framework defines the verified target operating posture of the VMware ESXi host environment post-migration to the Microsoft Azure cloud platform. The migration encapsulates standard configurations from original baseline provisioning documentation while expanding capabilities into an enterprise industrial context structured around a comprehensive Purdue Model for Industrial Control Systems (ICS).

2. Baseline Hypervisor Infrastructure Configuration

The core virtual processing engine maps into an Azure enterprise computing wrapper to sustain structural integrity and performance requirements:

  • Hypervisor layer: Deployed via native nested virtualization instances or Azure Dedicated Hosts executing the enterprise VMware ESXi core platform architecture.
  • Primary storage mapping: The hypervisor kernel accesses the OTCYBERDATAStorage namespace via native iSCSI or NFS mount layers over high-throughput, low-latency target endpoints.
  • Management control plane: Static localized IP allocation is maintained strictly at 10.0.0.150 via dedicated management virtual adapters (vmnic0 bridge topology). External dashboard console orchestration remains accessible via https://10.0.0.150 using authorized root administrative tokens.

3. Dual-Network Architecture Blueprint

To maintain operational resilience, clear data partitioning separates standard telemetry and business traffic from production control bounds:

  • VM Network (Internet Dynamic Stack): Leverages outbound programmatic NAT boundaries configured with automated DHCP address spaces, establishing isolated dynamic egress points for systemic patching and cloud intelligence updates.
  • ICS/OT Network (Operational Production Stack): Locked strictly into a rigid private structural layer bounded within the 192.168.169.XX network space, eliminating unauthorized lateral transitions.

5. Integrated Perimeter Security Controls

To safeguard the integrity of runtime operations, communication lines must follow rigorous zoning constraints:

  1. Traffic flowing between Level 5/4 and Level 3/2 must route through inspected stateful packet filtering structures. Deep inspection paths evaluate industrial protocols.
  2. The OT_SIEM (Security Onion) is fed using continuous internal port mirroring or virtual TAP switches to capture underlying cross-level flows for near-real-time intrusion assessment.
  3. Management interactions targeting the host dashboard console (10.0.0.150) must terminate exclusively within designated enterprise secure boundary jumps.
