1. Project Overview

This project builds a small, isolated ICS/OT security laboratory around a Rockwell Automation 1794-AENTR Flex I/O Ethernet adapter and a Raspberry Pi running Kali Linux. The lab is designed for repeatable observation and analysis rather than testing against production equipment.

Learning objectives

  • Verify communication and establish normal device behavior.
  • Perform disciplined reconnaissance using controlled discovery and passive capture.
  • Conduct non-destructive laboratory exercises and observe device/network responses.
  • Capture packet traces, logs, and device state for analysis.
  • Produce reproducible findings with evidence, limitations, and mitigation recommendations.

6. Wireshark Capture & Observation

Use Wireshark to capture traffic on the isolated lab interface. Save the capture in PCAPNG format so the evidence can be reviewed later.

Useful display filters

ip.addr == 192.168.169.60
tcp.port == 80
tcp.port == 44818
ip.addr == 192.168.169.60 && tcp

Observe

  • TCP connection establishment and termination.
  • HTTP request/response behavior on port 80.
  • EtherNet/IP traffic on TCP 44818.
  • Retransmissions, resets, connection rates, and timing.
  • Any change in device LEDs, web interface responsiveness, or communication state.

Do not interpret a high packet count alone as proof of a denial-of-service condition. Correlate packet counts with connection behavior, TCP flags, timing, device state, and the exact test that generated the traffic.

7. Non-Destructive Traffic Test

The source document included an unbounded multi-threaded HTTP request loop. For a reusable lab guide, it has been replaced here with a finite, rate-limited test so the exercise remains controlled and reproducible.

Bounded HTTP connectivity test

import time
import requests

target = "http://192.168.169.60"
requests_to_send = 20
delay_seconds = 0.25

for i in range(requests_to_send):
    try:
        response = requests.get(target, timeout=2)
        print(f"{i + 1:02d}: HTTP {response.status_code}")
    except requests.RequestException as exc:
        print(f"{i + 1:02d}: request failed: {exc}")
    time.sleep(delay_seconds)

This test generates a finite number of requests and stops automatically. Run it only against the isolated lab device and monitor the device and packet capture while it executes.

Stop criteria

  • Unexpected device instability or loss of communication.
  • Loss of the device web interface.
  • Unexpected I/O behavior.
  • Any indication that traffic is leaving the isolated lab network.

8. PCAP Analysis with Scapy

The following cleaned analysis script loads a PCAPNG file, counts packet types, summarizes packets, and identifies TCP SYN and RST flags. It is intended for offline analysis of an existing capture.

from collections import Counter
from scapy.all import rdpcap, IP, TCP

pcapng_file = "/home/kali/1794_AENTR_DoS.pcapng"
max_packets = 50000
packets = rdpcap(pcapng_file, count=max_packets)
print(f"Loaded {len(packets)} packets")

protocol_counts = Counter(
    packet.name for packet in packets if packet.name
)
print("\nProtocol Distribution:")
for proto, count in protocol_counts.items():
    print(f"{proto}: {count} packets")

print("\nFirst five packets:")
for i, packet in enumerate(packets[:5], 1):
    print(f"Packet {i}: {packet.summary()}")

ip_packets = [p for p in packets if p.haslayer(IP)]
print("\nFirst five IP packets:")
for i, packet in enumerate(ip_packets[:5], 1):
    print(f"Packet {i}: {packet[IP].src} -> {packet[IP].dst}")

tcp_packets = [p for p in packets if p.haslayer(TCP)]
syn_packets = [
    p for p in tcp_packets
    if p[TCP].flags & 0x02 and not (p[TCP].flags & 0x10)
]
rst_packets = [
    p for p in tcp_packets
    if p[TCP].flags & 0x04
]
print(f"\nTCP SYN packets: {len(syn_packets)}")
print(f"TCP RST packets: {len(rst_packets)}")

10. Targeted Packet Analysis

The source document analyzed packets destined for 192.168.169.100. That address is the Kali host, not the 1794-AENTR target at 192.168.169.60. This edition corrects the target selection.

Correct target selection

target_ip = "192.168.169.60"
target_packets = [
    p for p in packets
    if p.haslayer(IP) and p[IP].dst == target_ip
]
print(f"Packets targeting {target_ip}: {len(target_packets)}")

For target-focused analysis, always verify the destination IP before interpreting packet counts as device-directed traffic.

EvidenceWhat to document
Destination IPConfirm traffic is directed at the 1794-AENTR.
Destination portSeparate HTTP/80 from EtherNet/IP/44818 and other services.
TCP flagsSYN, SYN/ACK, ACK, FIN, RST and timing.

12. Defensive Recommendations

The lab observations can be translated into practical OT security controls.

Observation / riskDefensive consideration
HTTP management interface exposedRestrict management access to authorized engineering/admin networks; disable unused services.
EtherNet/IP exposed on TCP 44818Segment control networks and restrict who can communicate with industrial devices.
Unexpected connection/reset activityMonitor connection rates and TCP anomalies; establish a baseline for normal device behavior.
Limited industrial-protocol visibilityUse OT-aware monitoring and validated protocol dissectors.
Traffic can affect device responsivenessUse rate limits, bounded tests, dummy loads, and explicit stop criteria.
Flat lab segmentFor advanced exercises, introduce controlled segmentation between engineering, supervisory, and field networks.
OT principle. Availability and safety take priority over experimentation. Security testing on industrial equipment should be planned around process impact, recovery capability, authorization, and evidence collection.
