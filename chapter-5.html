5.1 Realizing the Purdue Model Segmented Asset Matrix

Following successful block-level migration and ingestion into Azure Dedicated Hosts or nested compute instances, workloads must be partitioned to prevent unauthorized cross-tier lateral movement.

Step 5.1.1Virtual Network (VNet) Segment Separation Configuration

  1. Within the Azure Portal infrastructure workspace console, navigate to Virtual Networks.
  2. Define two explicitly separated, non-overlapping architectural subnet structures inside your enterprise cloud deployment perimeter:
    • VM Network (Internet Dynamic Stack Profile): Configured to handle standard system telemetry, outbound programmatic Network Address Translation (NAT) boundaries, and automated DHCP address mapping scopes. This handles external lines-of-sight for continuous software updating, code validation patching, and cloud intelligence data streaming.
    • ICS/OT Network (Operational Production Stack Profile): Locked down strictly into a rigid private structural layer bounded within the Class B network space parameters: 192.168.0.0/16 (Subnet Mask: 255.255.0.0)

This partition completely blocks dynamic external routing allocations, outbound internet translation tunnels, or open default cloud egress hooks to shield internal assets from discovery or exploit vectors.

Step 5.1.2Hardening Perimeter & Inspection Boundary Controls

  1. Stateful Filtering: Traffic flowing between Level 5/4 and Level 3/2 must route through inspected stateful packet filtering structures. Configure Next-Generation Firewall (NGFW) rule profiles to perform Deep Packet Inspection (DPI) on industrial automation protocol formats (such as ModbusTCP). Explicitly drop any incoming packet stream originating from the Level 5 or Level 4 scopes that attempts to establish a direct connection path down to Level 1 or Level 0 process automation loops.
  2. Configuring Port Mirroring for Telemetry Ingestion: Inside your virtual networking configuration settings interface, set up virtual TAP switches or continuous internal port mirroring rules. Designate the primary destination target ingress point of this replicated network traffic to feed directly into the OT_SIEM (10.0.0.181) virtual security monitoring platform stationed in Level 5 to maintain real-time threat monitoring and anomaly detection analytics across the production environment.
  3. Restricting Host Management Dashboard Access: Isolate the management kernel access console path anchoring back to your migrated hypervisor address host marker (10.0.0.150). Implement network access control lists (ACLs) that block any direct public or multi-tenant corporate routing access to this management endpoint. Enforce an access rule requiring all administrative sessions targeting hypervisor client consoles or vCenter frameworks to terminate exclusively within designated, multi-factor authenticated enterprise secure boundary jump systems.
