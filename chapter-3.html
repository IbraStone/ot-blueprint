3.1 Installation of VMware vCenter Server Appliance (VCSA)

To orchestrate enterprise-level agentless migration and centralize host tracking, a vCenter Server Appliance (VCSA) must be deployed directly into the ecosystem.

Step 3.1.1Installer Mounting and Resource Stage-1 Extraction

  1. From your administrative engineering workspace terminal, access your download staging repository.
  2. Locate the official enterprise vCenter Server Appliance (VCSA) installation package (VMware-VCSA-all-X.X.X-XXXXXXXX.iso).
  3. Right-click the file artifact and select Mount to bind the storage layout to a local drive letter.
  4. Using an elevated file manager tool, navigate into the mount hierarchy path: ...\vcsa-ui-installer\win32\
  5. Locate the execution engine binary file named installer.exe. Right-click and choose Run as administrator.

Step 3.1.2Stage 1 Setup Execution Workflow

  1. Within the unified installation engine home array screen, click on the Install button.
  2. Progress through the Introduction overview tab page by clicking Next.
  3. Accept the End User License Terms by ticking the verification checkbox. Click Next.
  4. Appliance Deployment Target: Input the connection coordinates for the bare-metal host machine created in Chapter 2. Enter target host destination 10.0.0.150, configure port mapping to 443, and fill in the root account identification credentials. Click Next and accept the host's thumbprint verification alert.
  5. Set Appliance VM Settings: Enter OTvCenterServer into the Target VM name parameter frame. Establish a high-entropy password block intended to lock down the appliance root user OS terminal account profile. Click Next.
  6. Select Deployment Size: Select an execution size appropriate for your corporate inventory footprints. For this validated architecture, set deployment size tracking to Tiny and storage processing to Default. Click Next.
  7. Select Datastore: Highlight the specific storage resource partition created in Step 3.2.2: OTCYBERDATAStorage. Check the toggle option for Enable Thin Disk Mode to conserve raw block assets. Click Next.
  8. Configure Network Settings: Map out the network footprint metrics precisely:
    • Network Location: Select the active network port group tied to your administrative routing range.
    • IP Version: IPv4
    • IP Assignment Type: Static
    • FQDN / IP Address: 10.0.0.200
    • Subnet Mask: 255.255.255.0
    • Default Gateway: 10.0.0.1
    • DNS Servers: 10.0.0.1 or your enterprise system DNS infrastructure.
  9. Click Next, review the generation parameter block array layout summary, and click Finish. Watch the installation progress bar execute. Once Stage 1 terminates successfully, click Continue to seamlessly bridge into the configuration phase.

Step 3.1.3Stage 2 Initialization Lifecycle Operations

  1. Read through the Stage 2 Welcome splash frame. Click Next.
  2. Appliance Configuration: Define the time keeping mechanics. Set Time synchronization mode tracking to Synchronize time with the ESXi host. Set SSH Access option configuration tracking to Enabled for administrative flexibility. Click Next.
  3. Create a New SSO Domain: Establish an isolated identity scope context:
    • Single Sign-On Domain Name: vsphere.local
    • SSO Password: Establish a unique credential string (This serves the global corporate administrator@vsphere.local account domain marker).
  4. Click Next, review the final analytical telemetry selection box, and clear or accept enrollment program checkmarks based on corporate compliance policies.
  5. Click Next, evaluate the configuration summary text report layout block, and hit Finish. Do not interrupt the operation while the system runs configuration routines. Once a completion alert window pops up, click Close to exit the tool.

Step 3.1.4Datacenter Clustering & Inventory Attachment

  1. Initialize an administrative browser window pane and target the path link: https://10.0.0.200
  2. Select Launch vSphere Client (HTML5).
  3. Authenticate to the master control layer using your identity credentials: administrator@vsphere.local and your custom SSO password block.
  4. Right-click the root node configuration element marking the top inventory line identifier. Select New Datacenter.
  5. Input the enterprise name identifier string Azure-OT-Hybrid-Datacenter and click OK.
  6. Right-click the newly minted Datacenter object representation and select Add Host.
  7. In the wizard setup dialogue, target the base bare-metal platform configuration parameters:
    • Host Name or IP Address: 10.0.0.150
    • User Name: root
    • Password: Use your custom password block for the physical server machine.
  8. Click Next. Validate the host security handshake certificate verification thumbprint layout by selecting Yes.
  9. Review the connected virtual summary breakdown details. Assign an enterprise serial registration key block. Click Next.
  10. Leave Lockdown Mode configured to Disabled for baseline configuration staging. Click Next. Select your target Datacenter deployment location wrapper. Click Finish.
  11. Observe the background inventory reconciliation cycle. The bare-metal hypervisor node (10.0.0.150) alongside its primary underlying datastore structure OTCYBERDATAStorage will now register cleanly within your unified management hierarchy pane.

3.2 Storage Fabric Integration

This module guides you through connecting the localized hypervisor core file framework to the enterprise storage array partition layout.

Step 3.2.1Client Portal Console Authentication

  1. Initialize an administrative terminal connected directly into the local 10.0.0.X routing plane.
  2. Fire up a secure web browser utility and clear existing session tokens.
  3. Input the destination address link inside the locator frame: https://10.0.0.150
  4. Disregard localized self-signed SSL certificate alerts by clicking Advanced → Proceed to Target.
  5. In the enterprise VMware Host Client access grid, enter the administrative user designation root along with its associated secure password block, then click login.

Step 3.2.2Mapping the OTCYBERDATAStorage Target Array

  1. Focus your attention on the primary user interface navigation pane positioned on the left side of the dashboard. Expand the Navigator tree root node.
  2. Click cleanly on the Storage option configuration entry sub-item.
  3. At the top configuration tool strip, click on the New Datastore functional execution button.
  4. Within the wizard panel workflow, select the option item Create a new VMFS datastore and click Next.
  5. In the identity string box, paste the exact alphanumeric identity text: OTCYBERDATAStorage.
  6. Locate and highlight the underlying hardware disk storage partition structure provisioned via your external array setup. Click Next.
  7. Under the system deployment criteria options, enforce a VMFS 6 file system partition standard. Select the radio toggle to consume Use full disk capacity.
  8. Click Next, review the parameters summarized on the terminal view, and click Finish. Acknowledge the permanent storage erase pop-up warning by selecting Yes.
  9. Monitor the recent tasks drawer tracking console located along the base of the interface window. Validate that the volume creation cycle terminates with a green checkmark status indicator. System administrators can now safely load, build, format, and scale Guest production VM elements.
